# GitHub issue tracker

工程议题和执行 brief 使用 [CleverC2200/oa-approval 的 GitHub Issues](https://github.com/CleverC2200/oa-approval/issues)。

## 操作入口

优先使用已连接的 GitHub 插件，并显式选择 `CleverC2200/oa-approval`。插件缺少所需能力时使用 `gh`；仓库操作传入 `--repo CleverC2200/oa-approval`，REST 操作使用 `repos/CleverC2200/oa-approval/` 路径。

多行正文和评论通过结构化参数或 `--body-file` 提交。写入前读取完整议题及评论，标签按 [triage 标签映射](triage-labels.md) 处理。

通过 triage 发布的每份 issue 正文和评论均以以下声明开头：

```markdown
> *This was generated by AI during triage.*
```

公开议题仅记录工程行为、接口和脱敏验收条件。真实审批材料、个人信息及本地运行记录的边界遵循 [SECURITY](../../SECURITY.md)。

## PR 范围

**PRs as a request surface: no.**

triage 自动发现仅查询 issues。用户显式指定 PR 时，读取其正文、评论和 diff 后按 triage 流程处理。GitHub issues 与 PR 共用编号，裸编号先解析实际资源类型。

实现改动的分支、PR 和合并门禁遵循 [项目约定](../../AGENTS.md)。
