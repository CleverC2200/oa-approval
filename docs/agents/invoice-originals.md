# 关联发票原件读取

发票云原件保留明确返回的记录身份和票号。原生文档路径要求 `oa.doc_id/img_id` 齐全。PDF 要求 `modify_info.pdf/furl` 指向同一份有效 PDF。存在多个 PDF 时，还须有 `fileType=2`，且两个引用选中同一唯一候选。无有效 PDF 时，JPEG 要求唯一有效 `jpg/jpeg` 文件、`modify_info.pdf` 为空且 `furl` 指向该图片。云文件 ID 与 OA 主文件 ID 分属两个来源，不能互换。无法确认映射的文件保留未读。已绑定 PDF 同时带其他格式文件时，分别记录各文件的正文覆盖状态。

OFD 原件同时提供官方 PDF 阅读件时，仅在同一票记录、唯一有效 OFD/PDF、`fileType=4`、`furl` 精确指向 OFD、`pdf` 精确指向 PDF 且 OA 文档及文件身份均明确时读取该 PDF。冻结来源保留 OFD 云文件身份与 `official_pdf` 关系；不能把 OA 的 OFD 原文件字节当成 PDF。PDF 沿现有发票云下载链读取，仍执行下载前后关联、账号、文档及主文件核验；OFD 分项保留未直接读取状态。

官方 PDF 对应的 OFD 若在 OA 中保存为空 HTML 文档的唯一附件，空主文件本身不能证明归属。必须使用当前账号核对文档，并通过官方只读关联确认该文档唯一文件为同一 OFD 附件；初始化和下载前后均核对。缺失、多关联、附件角色不符或非空主文件不匹配仍停止。其他 PDF/JPEG 保留原有主文件校验。

下载前重新读取当前流程及关联票资料，核对请求身份、六类流程配置、关联票 ID、票号和完整原件映射，再以当前 Cookie 核验账号。有 OA 文档映射时还须核验原生文档的文件身份。缓存命中也执行下载前核验。原生文档读取被拒绝时，沿同一可信关联解析文档，通过 `basicInfo` 在共享初始化前后核对文件。初始化使用 `isrequest=1` 和当前 `requestid`，随后以同 Cookie 同 URL 重试一次。原生访问可能触发 OA 正常共享初始化，不修改权限配置或发起审批。

原件沿普通下载和冻结资源链进入材料。PDF 全页准备，JPEG 按图片原件保存并完整解码验证，成功准备后计为一页。正文覆盖状态以[观察合同](../../.agents/skills/oa-finance-preaudit/references/observation-contract.md)为准；明确绑定原件的下载或准备失败继续停止当前取材。历史冻结材料和意见不改写。

2026-10-18 的原生页面及[发票云前端源码](https://inc.mypiaojia.com/corpInvoice/js/jsapp.1792139559024.js)对照确认，部分关联原件在上述身份及上下文核验通过后，OA 文档下载仍拒绝，而原生发票详情可以下载。该场景使用同一发票云的 `GET https://api.mypiaojia.com/invoiceApi/file/download`，`id` 为已绑定原件的云文件 ID，`fid` 为当前关联票的云记录 ID，`dataId` 为当前流程的关联票引用，`token` 取现有 OA 发票云令牌入口。真实对照下载的 PDF 与原生页面下载包内原件字节一致。

当前流程明细的「关联发票」在发票云中已有明确记录和票号，且 `oa` 对象中的 `doc_id/img_id` 均缺失或为 `null` 时，可按官方页面路径读取 PDF。须有 `fileType=2`，有效文件只有一份 PDF，且 `modify_info.pdf/furl` 均精确指向该 PDF。部分原生映射、畸形原生 ID、候选不唯一或引用冲突时，保留对应缺口。2026-11-24 的三份只读对照均符合此条件，官方接口返回的 PDF 与原生页面下载包内相应 PDF 字节一致。

官方页面路径以发票云记录及文件 ID 标识资源，保留当前请求的关联票引用、票号及明细出处。只接受 HTTP 200 的完整 PDF 响应，分段响应保留为技术失败。

发票云下载前后核对同一流程、账号及完整映射。有 OA 文档映射时还须核验原生文档及文件身份。发票云下载拒绝重定向，正文限 50 MiB，并沿原件准备流程核对内容覆盖。权限拒绝或核验失败时停止取材。发票云请求只用当前令牌，令牌不写入资源、缓存或错误信息。
