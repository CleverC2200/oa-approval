# 经销商关户审批

执行用户于2026年11月4日确认的业务口径，交付逐单意见及可回查依据。默认只读核对与意见生成；业务口径确认不等于OA写入授权。

业务基准为[关户审核第1节](https://klvcodtump.feishu.cn/docx/ZYkMdZ08XoGdkaxpwTTcCa7unme#doxcncAssT4zifmh3RHVhBZ376d)。每轮读取当前版本并记录修订号，本文件保留已确认的补充与分支差异。新的实质冲突列明影响，继续已明确项目。

## 1. 确认单据与分支

读取指定申请或本次关户待办的表单、资源、历史意见和实际流转节点。当前流程为`经销商管理-关户`，已核流程ID为`195127`，使用时核当前定义。

每单固定申请ID、流程编号、公司编码、客户编码、客户名称、表单有无余额分支、是否退款、申请金额和审核截止日。外部取数按公司及客户精确匹配，名称相近或同一法人不能替代客户编码。待办转发入口与实际节点分别记录，已归档单只作历史复核。

| 分支 | 执行标准 |
| --- | --- |
| 表单无余额关户 | 核当前余额及必要结转依据；不涉及退款，对账单非强制。零金额下“是否退款=是”不单独列异常，旧标题“有余额”不覆盖当前表单分支。 |
| 表单有余额、实际申请退款 | 核退款金额、适用签署资料及账户，同时核账务。 |
| 表单有余额、不退款 | 核余额去向或处理依据；退款书不适用，不从个案推导通用小额豁免阈值。 |
| 历史有余额单已退款记账，当前余额0 | 保留历史申请分支并核后续凭证，不再次列旧申请金额为可退金额。记账与银行到账分别表述。 |

完成条件：身份、截止日和分支可定位，表单与当前余额的时点差异已解释或列具体待核。关键身份不明时先交付读取未完成说明，不形成业务结论。

## 2. 取得本轮事实

连接或取数时读取[只读数据入口](references/read-sources.md)的对应段落，复用现有OA、BI、正式SAP及DMS能力。请求、响应、时点、源版本、分页完整性及错误保留私有运行目录；真实材料与意见留在Git忽略目录。

| 审核项 | 来源与标准 |
| --- | --- |
| 客户预付款余额 | BI客户余额与余额显示；解释差异时核正式SAP客户账。按已确认借贷方向表达，客户借方余额不能取绝对值冒充预付款。 |
| 下单剩余、占单 | 正式SAP有效报表，或按当前活动源码及完整底层数据复算。复算与直接报表响应分别记录，BI另一个剩余字段不替代SAP口径。 |
| 预提、特别总账 | BI指定报表；非零余额、处理凭证或差异定点追至原科目、客户归属和有效抵消记录。 |
| 发货权限 | BI状态，必要时核SAP对应字段。信用、订单、交货和过账冻结分别记录，不能互相替代。 |
| 免投冰柜 | 当前有效系统数量，或明确客户、范围及时点的业务确认。确认无时意见直接写“无免投冰柜”，来源另存。新单空值仍待核，历史批次确认不自动继承。 |
| 三方融资 | BI约定结果；核近6个月范围和已有明细。抬头关键词为华润、网商、民生、中信经营贷、菜鸟、京东、浦发。 |
| 最后发货后补贴 | BI约定结果；核最后实际发货期间及其后费用。过账月份与费用所属月份分开，后月入账的前月费用不能直接当作后月新增补贴。 |

使用用户指定截止日；未指定时取本次审核日，记录时区和近6个月窗口。已知期初导入、截断或日期覆盖不全时保留具体缺口。BI约定来源的0可按来源列示，不为每个0开展无边界全账扫描，也不把已知覆盖缺口写成已证实无融资或补贴。

完成条件：所有适用项目均有本轮原值和来源，或明确缺失/失败及其影响；空值和截断已识别。

## 3. 核对账务

- 同公司、客户、币种和相同时点的同义金额才比较。多科目行重复的客户余额不直接累加，保留明细粒度与来源聚合口径。
- 预付款、下单剩余、预提、占单分项列示。BI预付款与SAP一致时，不能因BI另一个剩余字段为0写“账面余额不一致”。未证实的字段映射留技术核对，不冒充资金异常。
- 预提、特别总账、占单、免投冰柜非零，权限未锁及发货后实际新增补贴，列项目与金额/状态。原规则要求列示，不自行推导统一退回、抵扣或放行策略。
- 核原科目、借贷方向与冲销链。同额凭证在另一科目，或后续凭证已冲销，都不证明原余额清零。预提不自行从预付款扣除计算退款。
- 有效凭证已解释的结转或退款记账不再列未解释差错，不再次建议相同退款；记账不能证明银行到账。

完成条件：异常与未核实项分清，金额差异可定位两侧字段、时点和差额；已查清处理记录不再留业务猜测。

## 4. 核对适用材料

无余额分支沿第1步执行，不因缺对账单、缺退款书或零金额退款字段形成材料异常。

有余额退款分支核对：

- 对账单最新签署月份及余额与对应账务时点的关系。DMS“签署完成”即认可签署，不因预览PDF无章要求补签，也不要求先取得盖章PDF；金额仍从结构化数据或既有材料核对。
- 退款书客户名称、金额及大写；与BI、申请不一致时列具体差额。公户、法人或DMS已报备账户合格；未取得报备且公户/法人身份未明时，写实际缺口或已证实不合格依据。
- DMS退款查询为空时继续核OA有效原件。接口为空不等于没有退款书，保留实际来源。
- 适用1+N合同时只核签署状态，不要求附件；不替代其他单据的签署，也不额外给每单增加1+N条件。

完成条件：适用材料已核或列具体缺口，政策非强制项、无记录和技术读取失败分别表达。

## 5. 生成与交付

按[结果合同](references/result-format.md)逐单保存意见和核对记录。✅合并正常项，❗保留具体异常、金额及必要处理；接口、算法和取证过程另存。关键待核存在时，✅只标已核项目，不写整单全部审核无误。

交付前覆盖第2步全部适用项目，确认分支豁免已应用、异常未被合并丢失、身份与金额对应、证据可回查。汇总已核单数、含异常或待核的单号、意见绝对路径和本次是否实际提交。

当前通用费用预审批次未接入关户流程。本Skill先复用只读来源完成审核，不将关户伪装成费用流程。后续明确要求真实提交时，先确认公开能力已支持关户采集、意见、提交登记和回查，再按有效授权执行；能力未覆盖时先补接线。已归档和结果不明单据分别走历史复核、只读回查。
