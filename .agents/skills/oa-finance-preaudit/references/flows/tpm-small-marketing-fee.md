# TPM 小额市场费规则包

适用于 `workflow_key=tpm_small_marketing_fee`。复用[共享结果接口](../result-contract.md)和公共取数、证据准备及意见输出；差异仅在本流程的科目、附件要求和以下四项规则。不得套用普通小额市场费的 SAP 客户编码或费用承担主体要求。

财务共用的金额与表达要求见[财务意见补充要求](../finance-result-contract.md)，付款、发票和识别覆盖见[财务证据补充规则](../finance-observation-contract.md)。

AI 只形成预审意见，不批准、不退回。判断来自当前流程可回查的字段、关联发票和附件内容。附件缺失属于业务问题；自动读取失败时按[执行接口](../execution-contract.md)停止当前单据审核与提交，不得声称申请人未填写字段、未上传附件或单据没有发票。问题结论应指出具体材料、金额或关系，不要求固定句式。

## 固定四项审核

1. 附件完整性：读取各明细预算科目，仅按该科目匹配下表，不按标题或报销事项追加其他科目的要求。同科目的共用制作清单和照片可在整单范围核对，不要求每行重复上传；字段未解析时，仍需检查当前单据已取得的附件内容，不直接判缺。科目可读但不在表中时，按支付截图和发票检查，不因表外科目单独提示异常。科目本身读不清时说明无法确定适用要求。缺支付截图时，按[六类财务共用规则](../payment-screenshot-exemption.md)核验对公付款豁免。其他必需附件仍需核对。清单盖章、现场定位及照片要求都在本项核对。材料里存在可查看的原图时，必须实际读取清单及照片，按[附件观察入口](../execution-contract.md#附件观察)记录真实资源 ID、页码/区域、原值与核对结果；不得用附件名称、文件大小或上传存在性代替内容核对。未完成照片与清单内容核对时本项使用 `⚠️`，说明具体未核事项；是否通过由审核 Agent 按材料判断。
2. 发票关联与金额：核对当前单据 OA“关联发票”及发票金额，同一发票去重计入。单据内已关联发票不要求逐行重复挂票，也不额外要求提供发票金额逐行分摊表；发票挂在某一明细行上不等于金额只属于该行，不能直接把整张发票总额与第一行金额不同判为冲突。存在多支付对象、跨单据或重复票据等明确问题时，再按实际对应关系核对，不凭金额相同推断其他单据或附件的归属。仅纸质发票或收据才核对快递单号、是否已传递或邮寄；收据另核对购买方、事项、金额、收款人姓名、身份证号和手机号。没有纸质发票或收据时，不提示该项附加要求，不另设签字栏目。电子发票本身不是问题。
3. 金额孰低核销：核对可信支付金额、发票金额及适用的盖章制作清单金额，按孰低原则形成核销意见。仅预算科目为 `终端建设费-终端形象制作费` 时，须核对并说明盖章制作清单总额；`推广费用-物料费` 不追加清单盖章要求。已确认对公且免支付截图时，使用申请支付金额与当前单据已关联发票金额核对，申请金额不能写成已实际支付，也不因支付状态为空而另报缺少实际支付金额。多张凭证合计须有可信对应关系并排除重复截图；金额比较不设置容差；金额无法确认或存在明确归属冲突时，说明待核实事实，不因缺少逐行分摊信息单独提示异常。已提供材料中的支付失败、重复和金额冲突仍需报告。
4. 支付公司一致：本流程比较公司名称时，仅统一中英文括号并去掉首尾空白，这些排版差异不构成主体差异；仍保留原值，不改字、展开简称或做模糊匹配。核对实际报销公司、支付公司及权威发票购买方，完整原值和比较依据留在核对记录；签字意见按下文只写一致结论及实际支付公司全称，存在冲突或缺口时保留具体事实。`zfgs` 是实际支付公司，`zfgswb` 是支付公司文本，`zfzhmc` 是支付账户名称，`bxgs` 是报销公司；`zfgs2` 仅是辅助“支付公司2”，`kpgs` 是开票公司。辅助支付公司或开票公司与购买方相同不能证明实际支付主体一致。保留全部原值、读取状态和来源，实际字段冲突时不得任选相同的一项替代其他字段。无法确认时列出缺失字段或冲突原值，不猜测公司对应关系。收款人与销售方关系属于第一项的支付截图豁免条件，不独立增加审核项。

## 10 类费用科目与附件要求

| `推广费用-物料费` | 发票、制作清单或购买明细、支付截图、制作完成定位照片 | 清单或明细与定位照片一致 |
| `终端建设费-其他` | 发票、支付截图 | 按通用发票和支付对应关系核对 |
| `通路促销-订货会会务费` | 关联申请签报、发票、费用清单、签到表、支付凭据；每个申请不少于 4 张订货会现场多角度全局定位照片 | 逐个申请核对照片数量、全局视角和定位信息，缺少会议材料时明确列出 |
| `推广费用-产品赠品费` | 发票、支付截图 | 按通用发票和支付对应关系核对 |
| `推广费用-试吃品费` | 发票、支付截图、执行试吃定位照片 | 说明照片缺失或定位无法确认的具体情况 |
| `促销员费用-管理费` | 发票、支付截图 | 按通用发票和支付对应关系核对 |
| `促销员费用-激励费` | POS 复核数据表、激励政策（申请签报或签报截图） | POS 表只检查是否上传，不识别表内内容 |
| `促销员费用-统筹福利` | 关联申请签报、发票、支付截图 | 核对签报与当前明细的归属关系 |

## 制作单价核对（归入第一项）

TPM 终端形象制作费的 `material.tpm_price_reference` 是本地导入并随材料冻结的参考报价。先确认清单属于当前明细，再匹配参考物料；参考表本身不证明当前单据的支出、数量或附件完整。行号和来源哈希用于回查，不把参考表当成 OA 附件，价格适用性按本节核对。

只对预算科目为 `终端建设费-终端形象制作费` 的明细逐项执行，混合科目单据按对应清单范围检查；不扩展到“推广费用-物料费”。先核实清单与明细的归属，再读取冻结的 `material.tpm_price_reference`。`status=ready` 时，`rows` 是财务参考表的物料、规格、单位和 H 列“含税指导价（元，1%）”；`source_row` 是原表行号。此表是共同审核基准，不是当前单据的支出证据。`ready` 只表示文件读取和结构校验成功，不能证明价格仍适用；来源哈希和文件修改时间也不代表业务生效日期。使用前核对财务确认的适用范围，时效无法确认时如实提示待财务确认，不擅改价格或补写确认日期。

- 逐项核对清单的材料编码、名称、材质规格及计价单位。编码和名称指向不同物料、规格不清或参考表无对应项时，说明具体冲突或缺口，不任选一个价格、按相近名称套价或猜测缺失规格。
- 按参考单位比较。清单按块或套、参考按平方米时，只有尺寸、数量和组合构成明确才能换算：单块面积为换算到米的长×宽，元/块除以单块面积得到元/㎡；多块合计金额须除以对应总面积。异形计价、损耗、双面计费或套装不明时不套用长宽公式。保留原单价、尺寸、换算过程和来源；比较前不四舍五入掩盖差异，展示时可以合理保留小数。
- 一律采用 H 列原值，不按发票税率调整，不因清单没注明税率而另加税额。比较范围不含安装和运输；已单列的安装运输行不参与制作比价，合并报价只有可信分项金额时才拆分，否则只说明无法准确比价。先确认材料、单位及费用范围一致再判断高低；无法拆分时不得将含安装运输总价与纯制作指导价比较并标为偏高或偏低。安装运输不参与比价不等于从原核销金额中剔除。
- 高于、低于指导价均不设允许偏差，在第一项简短列出“物料、清单单价、指导价、差异方向”；同类差异可合并，但覆盖所有异常物料。价格差异或无法比价时第一项使用 `⚠️`，只列实际价格差异或匹配缺口及待核状态；差异原因的分析留在核对记录中，不仅凭差异认定不合理。已确认缺件等原有 `❌` 仍保留，同时列出价格问题，不用价格提示覆盖其他异常。
- 在本次工作上下文定位实际使用的 `material.tpm_price_reference.rows` 索引、原表 `source_row`、预算科目完整字段路径和清单内容；附件部分通过观察入口保存，覆盖每个适用物料的一致、差异或无法比价结果。公开意见只列具体差异或缺口，其他项目不重复价格警告。参考表未配置或不可读时只写 `参考报价未取得，制作单价待核。`；来源定位不能替代 Agent 逐项比价。
- 第三项继续核对可信支付、发票和适用盖章清单金额，不把“指导价×数量”加入孰低核销，也不因高于或低于指导价改写核销金额。四项结构保持不变。

## 签字意见

签字意见完整保留上述四项，复用公共输出：通过显示 `✅`，明确不符显示 `❌`，证据不足显示 `⚠️`。通过项只写一句给审批人的结论，不复述取证过程、明细数量、图片覆盖、字段路径、文件位置、豁免推理或发票挂票位置。四项正常结论按以下语气写：

- 附件完整性：通过写 `附件完整。`；确认缺件时按行写 `第 N 行缺少 XXX，请补充。`（多行用顿号并列）；无法比价或价格异常按上文列明具体事项，请财务核实，不改写成缺少附件。本次核对记录保留该行 `yskm` 预算科目的完整字段路径。
- 发票关联与金额：通过写 `已关联发票，金额核对一致。`；OA「关联发票」全部未解析或为空且无其它可信关联记录时**不得判通过**，写 `发票关联待核。`，不得用附件名称、附件内发票号或金额相等替代关联关系，也不得把未解析字段列为通过证据。实际金额冲突在本项列明必要数值，第三项只承接其金额影响。
- 金额孰低核销：正常时写 `按 X 元核销。`；适用盖章制作清单时另写 `盖章制作清单总额 C 元。`。金额不一致时只列形成差异的金额、差额及核销结果；尚未确认整单上限时保留已确认小计和待核范围。金额名称按来源写“实付”或“申请支付”，不用申请支付金额冒充实付，也不展开孰低算式。
- 支付公司一致：通过时写 `报销公司、支付公司、购买方一致，使用 XXX 账户支付。`，XXX 为原单实际支付公司全称。主体不一致时列出实际报销、支付主体和购买方差异；辅助字段的原值和处理依据留在核对记录中，影响主体判断的冲突仍须披露。证据不足时具体说明缺失或未解析事实。仅写 `使用 XXX（发票购买方）账户支付。` 是支付建议，不能作为一致通过的结论。

有问题时才简洁写明具体缺口、冲突或需补材料。同一缺口在最相关项说明，其他项只说明受到的实际影响，不复制成多条警告。不再输出仅含问题的清单。

## 公司核对记录与历史材料

按第四项逐个核对报销公司、实际支付公司、支付账户、发票购买方及辅助公司字段的角色、原值、读取状态和来源。附件事实通过[附件观察入口](../execution-contract.md#附件观察)保存，表单及权威事实在本次工作上下文保留来源路径。公司一致才使用 `✅`；明确不一致为 `❌`；实际支付公司、报销公司、权威购买方缺失或无法消解角色冲突时使用 `⚠️` 并写明缺口，不能仅给账户建议就判通过。

历史冻结规则、材料和已提交意见按当次版本回查，不添加新字段、不改写历史意见或自动重新提交。新任务从当前适用规则重新取材、完整审核。
