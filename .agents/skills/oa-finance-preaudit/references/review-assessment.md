# 提交前审核结果

## 有界读取

规则与材料分别读取。冻结材料正文通过现有材料 CLI 分页，每次工具调用只返回一页；不要先把整份材料和嵌套订单合并打印后再补读。首段示例：

```bash
bash .codex/python.sh -m apps.oa.materials read "$OA_MATERIAL_FILE" --format json --page-offset 0
```

每页最多2000字符，返回当前材料 `material_sha256`、`offset`、`end`、`total_chars` 和 `next_offset`。后续段使用同一材料、同一 `--pointer` 和返回的 `--expected-sha256`，将 `next_offset` 作为下一次 `--page-offset`，直到该范围读完。原值、换行及资源身份完整保留；换材料或混用版本会被拒绝。为每页 JSON 元数据和正文留足工具输出预算，必要时缩小 `--page-chars` 后回读该段。

`--pointer /authority_facts/0/value` 可定位原 JSON 的具体值；字符串原样分页，其他对象完整序列化分页，不按摘要替代原文。`--view outline` 也可分页，但只提供定位，不计正文已读。按本单适用范围保存所读 Pointer 及连续字符范围，完成全部适用材料、明细和原件核对后再交审核结果。`next_offset=null` 只说明当前范围没有下一段，不证明其他范围或业务审核完成。原图识别仍使用本流程规定的专用入口。

输出不完整时，先保存原工具会话、命令、输出预算及截断位置，区分以下情况后处理：

| 发生位置 | 恢复与完成条件 |
| --- | --- |
| 累计进度日志被工具省略，原进程仍运行或最终报告已经落盘 | 等待原工具会话；必要时用公开 `materials progress` 核对同一报告。日志不是附件正文，不据此登记材料读取失败或停止补位。报告失败时按其真实失败处理 |
| JSON 投影打印了不需要的嵌套正文，或工具输出截断了材料、识别正文 | 保留该次证据，改用同一文件的有界读取，按 Pointer 和连续字符范围补齐全部适用正文。元数据投影逐项列出所需键，避免仅排除 `value` 却漏出 `raw_value`。工具调用外层和子命令均留足输出预算，每次只返回一页 |
| 正文分页仍不可读取、源文件缺失或变化、识别服务明确失败 | 保存具体来源及恢复尝试，登记实际未完成或技术失败，按既定保护收尾 |

恢复只纠正读取方式，不重新采集或改写冻结原件，不把报告 `complete` 当作业务审核完成。补读后核对同一文件摘要、连续范围及全部适用明细，完成核验才交付意见。已经登记的同轮同材料 `incomplete` / `technical_failure`、未知提交和原件归属保护继续生效，不能用补读清除；历史失败仍须按精确授权重新采集。

## 审核交付

本流程允许使用附件识别入口时，局部复读先从已完成原页报告的 `source_image_size` 核对尺寸，再以旋转前原图像素填写 `--region X0 Y0 X1 Y1`。确认选区覆盖目标文字，不凭屏幕显示比例猜坐标，不自动截掉越界部分。

`status=failed` 且 `failure_stage=selection_validation` 表示选区在送交模型前被本地校验拒绝。保留该失败报告，按返回的原图尺寸重新确定选区，用新输出目录完成复读；失败报告本身不能作为完成识别提交。只有修正后的识别和全部适用核对完成，才能交付完成结果，证据文件保留原拒绝报告及新的复读报告。这只适用于登记审核失败前的选区参数纠正，不适用于原件缺失或变化、权限、模型读取失败或未知提交；已经登记的 `incomplete` / `technical_failure` 仍须按精确授权重新采集，不自动解除保护。

审核 Agent 在最终交付中增加独立的审核结果 JSON 文件，主 Agent 核对后通过 `submit --review-file <绝对路径>` 提交；真实写入必需，海外也沿用此绑定检查。该文件记录已实际执行的核验，不由模板或脚本代填完成结论：

```json
{
  "task_id": 123,
  "material_sha256": "本次公开show中的task.material_sha256",
  "status": "business_pending",
  "reason": "具体已核事项和仍未知的原值，不把未知填零",
  "rule_basis": "当前冻结流程允许保留该未知并交后续判断的具体规则",
  "evidence_files": ["本次material_file绝对路径", "本次原始识别和复读报告绝对路径"]
}
```

`status=complete` 表示全部适用审核已完成且无遗留待核；`business_pending` 表示已完成全部适用处理，按具体流程允许保留业务未知，两者可按授权提交。`incomplete`、`technical_failure` 表示审核未完成，不允许提交完成意见；通过 `fail --task-id ... --reason ... --review-file ...` 保存绑定的失败证据并登记，无需编写意见。采集阶段未形成冻结材料的异常仍由 collect 的诊断入口记录。

证据文件位于本次 `material_file` 的版本目录内，包含本次适用原始识别、复读及观察文件；身份、材料版本、文件归属和存在性由入口核对。程序在预测或外部写入前持久化审核结果及证据摘要。业务待核、审核未完成、读取失败及没有结构化结果的历史材料均保留；提交成功不清除这些保留事实。

入口发现失败识别、未完成读取或冻结材料变化时自行保存 `review-errors` 诊断及实际的 `technical_failure` / `incomplete` 事实，返回 `diagnostics_file`；不能通过下一次省略报告解除同轮、同材料版本的未完成保护。识别仍运行时先等原工具，完整审核后再首次提交；已经交回未完成结果的单据按公开 `fail` 收尾，已有服务端证据时无需重写审核结果文件。后续重试仍按既有精确授权重新采集、完整审核，不自动恢复旧意见。

局部文字不清、金额存在业务冲突或关系未知，按流程完成本单处理后继续 FIFO 补位。只有恢复后仍未解决的正文读取失败、正文截断或已核实的主会话上下文达到60%才适用小时任务提前停止保护；本单业务未知不等于整批无法读取。
