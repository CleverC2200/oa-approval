# 小时检查与连续处理

本文件仅供定时任务及其接续对话的主 Agent 读取。审核与排空使用[批次执行规则](batch-execution.md)，业务审核使用 [Skill](../SKILL.md) 的流程路由。授权统一遵循 [SECURITY.md](../../../../SECURITY.md)。

## 启动与互斥

每小时检查用于空闲时发现待办。有积压时按下文立即接续独立对话，不等待下个整点。自动任务保持用户设定的启停状态；暂停后不创建新接续对话。

1. 从 `/Users/synear/Documents/OA` 读取当前 AGENTS.md。小时任务及接续固定使用 `/Users/synear/Documents/OA/runtime/hourly-preaudit`，保留同一 SQLite 账本与材料。首次使用共享锁版本前确认旧版本 owner 已结束，正在审批的 checkout 保持原样，空闲后再同步主线。
2. 用公开 `approvals --root <固定目录> status` 检查已有轮次及 owner。owner 可达时跳过本轮；失联的 running/blocked 或未知提交先报告核对。小时初始检查遇到待消费接续时不重复创建对话，保留事实并报告。已获派发的接续对话携带精确 `previous_run_id`，核对它是当前最新轮次、状态 closed、handoff 为 ready 且 owner 不可达后，继续执行 `--continue-from`，不把该合法接续当作阻断。
3. 空闲后 fetch `origin/main`，确认分支为 main、工作区干净且 HEAD 与 `origin/main` 一致。失败即停止，不自动切换、重置或拉取合入。
4. 初始轮使用 `start --batch-size 40 --limit 0`，显式限定当前授权的流程。非 demo 的审批入口先取得项目共享 `runtime/approval.lock`，再取得本轮目录锁；任一 runtime 有 owner 时，第二个启动返回 `already_running`，尚未读取 OA 或建立队列。收到该状态直接跳过，不等待或换目录绕过。

## 持续补位与对话轮换

- 每个主对话最多领取 40 单，批次内保持最多 3 单在途，一单结束后及时补位。审核 Agent 每代最多 5 单及换类型轮换沿用批次执行规则。完整业务核对要求保持不变。
- 有积压就持续处理，取消按运行时长停止补位。主对话可见上下文达到窗口 60% 或已经影响读取质量时，提前停止领取并排空；平台未提供可靠占用时使用 40 单边界，不估造 token 数。
- 主 Agent 仅保留状态、身份和文件引用。CLI 原始 JSON、完整材料、意见和逐页结果保存在 runtime，审核 Agent 从文件完整读取。
- 初始待办不足 40 单时处理实际数量。技术失败和预览也占领取数；连续链内已处理的任务身份保存在账本，后续轮不重复预览或重试失败单。OA 再次投递的新任务身份仍可进入队列。

## 排空后立即接续

仅在当前授权仍有效且需要清理积压时使用以下入口。用户停止、任务暂停或未知提交时，按批次执行规则收尾，使用普通 `finish`，不请求接续。

1. 排空已领取单据并核对身份、材料及回执。执行 `finish --run-id <本轮ID> --handoff`，保存最终 JSON，等待原 owner 工具会话退出，再用 status 确认 `run.status=closed`、`owner.reachable=false`。提前因上下文轮换时，只验收已领取单，queued 保留为下一轮待办。
2. `handoff.status=done` 表示当前队列没有剩余排队单，本轮结束，等待下次小时检查。`blocked` 表示在途、未知、提交未验证或本轮未取得进展，保留具体原因并停止。仅 `ready` 允许创建接续对话。
3. 再核对自动任务 `oa-skill` 当前为 ACTIVE；暂停时保留接续事实并报告，不创建新对话。当前用户已经授权在这条连续处理链内创建接续独立对话，先调用 `list_projects` 定位本项目，再调用原生 `create_thread`，目标为本地项目，不指定模型，不创建工作树。
4. 新对话提示词包含固定项目目录、本文件和批次规则入口、此次返回的 `runtime_root` 与 `previous_run_id`、当前任务有效授权的原文及限制。子对话先核对主线和授权，再用返回的 `start_arguments` 启动，例如 `start --continue-from <前轮ID> --limit 0`，保留原流程、申请范围和每轮数量。初始轮和接续轮均重新拉取 OA 当前待办，不把旧批次名单作为当前待办事实。默认预览；真实写入仅沿用明确的持续写入授权，海外仍独立授权。
5. 原生工具创建成功后保留真实 threadId，按工具要求用一次紧凑状态快照确认已派发，然后结束当前主对话。新对话按同一规则工作和接续，不回传业务正文到旧对话。创建失败或结果不明时报告本地接续事实及原生工具结果，停止自动重试，不重复创建。

接续预留在关闭回执前写入 SQLite。普通 start 在预留待消费时返回 `continuation_pending`，不刷新 OA。`--continue-from` 只允许消费最新且 ready 的前轮一次；已经消费、错误身份或变更流程范围均在刷新 OA 前拒绝。下一轮排除本连续链已完成、已预览或明确失败的同一次投递，保留失败材料和回执；旧轮和原对话不再接单。

## 结束与反馈

无待办也关闭 owner。每轮报告只含领取数、已验证提交/预览/技术失败数、未领取数、接续状态、耗时及证据路径。区分队列耗尽、对话轮换、已有运行跳过和异常阻断。意见、数据库和回执保持私有；通知偏好由自动任务配置维护。自动任务记忆不累积业务材料、历史单号或旧队列。
