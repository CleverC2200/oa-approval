# 小时调度边界

本文件仅供小时定时任务的主 Agent 读取。审核方法和逐单收尾使用[批次执行规则](batch-execution.md)，业务审核使用 [Skill](../SKILL.md) 的流程路由。

## 启动与互斥

每次触发使用一个独立运行对话，仅处理本轮批次，结束后等待下次定时触发。沿用本项目本地模式和暂停/启用设置；调度不延续上轮对话，也不在同一对话连续开新批次。

1. 从 `/Users/synear/Documents/OA` 读取当前 AGENTS.md。先只读检查该项目 `runtime` 本身及其直属批次子目录中已有的 `approval.sqlite3`，逐个用公开 `approvals --root <绝对目录> status` 查询最新轮次及 owner 可达性。另核对本项目正在运行的审批 owner 进程，覆盖尚未生成数据库的启动阶段；进程身份或目录不能确定时报告阻断。
2. 任一 owner 仍可达或审批进程仍在运行，记录 `skipped_running` 并结束本轮；保留原批次及 checkout。旧轮为 `running`/`blocked` 而 owner 已失联，或仍有 `submitting`/`unknown` 时，报告需人工核对并结束本轮。历史 `closed` 和已明确结束的技术失败不代表当前仍在运行。
3. 空闲后 fetch `origin/main`，核对分支为 `main`、工作区干净且 HEAD 与 `origin/main` 一致，失败即结束并报告。沿用当前 checkout，不自动切换、重置或拉取合入。
4. 小时任务固定使用 `/Users/synear/Documents/OA/runtime/hourly-preaudit` 作为 `OA_RUNTIME_ROOT`，保留 SQLite 防重发账本和材料。启动时若返回 `already_running`，按 `skipped_running` 结束，不等待锁、不重试，也不换目录绕过。启动成功才保存本轮 `run_id`、批次范围和开始时间。

现有 `approval.lock` 只保护同一个 runtime 根目录。上述跨目录查询是提示词前置检查，与 `start` 之间仍存在竞争窗口。启用前需由审批入口提供跨 runtime 的共享互斥；验收应覆盖第二个目录启动返回 `already_running`、未读取 OA 或创建队列，以及原轮关闭后能正常启动。当前提示词不将前置查询视为原子锁，也不为绕过检查关闭其他轮次。

## 数量、时间与上下文

- 每轮最多领取 40 单，启动使用 `start --batch-size 40 --limit 0`，按当前授权显式选择适用流程。启动返回的范围即本轮上限，待办不足时按实际数量处理。真实提交必须有自动任务中明确保留的持续授权；默认预览，海外仍须独立授权。
- 从本轮 `run.started_at` 起满 50 分钟后停止新领取，完成已领取单据的审核、提交或预览，再按批次执行规则关闭轮次。这是领取时间边界，不是杀进程的截止时间；原轮跨过下次整点时，下轮跳过。
- 主对话可见的上下文占用达到模型窗口 60% 时，同样停止补位并排空。平台未提供可靠占用时，用数量和时间边界收尾，不估造 token 数。上下文提前吃紧也按此方式收尾，完整材料及业务核对要求保持不变。
- 数量、时间或上下文任一达到边界，即进入停止排空。技术失败和预览占已领取数量，剩余待办留给下次重新拉取。达到边界不扩大批次、不压缩业务核对，也不另起后台批次追赶积压。

审核 Agent 的每代上限与轮换沿用批次执行规则。主 Agent 只保留状态、身份和文件引用，完整正文由审核 Agent 读取。时间或上下文提前收尾时，只验收已领取单；保留本轮原始冻结范围和剩余 queued 数，不把未领取单记作失败或声称整个冻结批次已完成。

## 结束与反馈

无待办时也关闭本轮 owner。正常完成或停止排空后，确认 `run.status=closed`、`owner.reachable=false`，并保留逐单意见、回执和验收状态。未知提交按批次执行规则阻断，只读回查，不自动重发或恢复调度。

本轮摘要只含运行状态、领取数、已验证提交/预览/技术失败数、未领取数、耗时和证据路径。区分批次耗尽、边界排空、已有运行跳过和异常阻断。不要在自动任务记忆中累积业务材料、历史单号或旧批次名单；后续轮次重新查当前事实。通知偏好由自动任务配置维护。
